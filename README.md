## 项目简介
湿球计算器是一款基于气象学公式的图形化工具，用于计算湿球温度、露点温度及相关气象参数。支持多种饱和水蒸气压力计算公式，提供单位转换、迭代过程可视化及详细参数分析功能。
本项目作为我们降水相态的温度廓线研究的子项目，为主项目提供了强大的技术支持。提供本软件即旨在提供各类气象学研究的得力工具。

## 🔥 不只是一个湿球计算器。

### 🌟 核心优势

- **精度可复核**：14 种国际公式，其中 Goff / Goff-Gratch / Wexler 三条参考级公式与 WMO 参考表的偏差 **≤ 0.09%**；全部数字由 CI 每次推送自动复跑（见下方「实测能力与精度」）。
- **智能三模式**：支持已知湿球求露点，已知露点求湿球，甚至已知相对湿度求两者！（1.2.0 新增）
- **超高速批量计算**：（1.2.0 新增）将 xlsx 中所有数据一键批量计算！
- **扩展参数计算**：点击结果可进一步计算焓值、混合率、虚温、位温等 20+ 气象参数。
- **全单位支持**：支持温度（℃、℉、K）和压强（hPa、Pa、mmHg、cmHg、bar）的实时切换。
- **可视化拟合**：动态展示迭代收敛过程，洞悉算法稳定性。
- **输入校验在引擎层**：温度 −150~200 ℃、压强 (0, 1200] hPa、相对湿度 (0, 100] % 在计算核心里强制校验，非法输入给出明确错误而不是一个数字——批量计算路径同样受保护。
- **其他功能**：一键清空、截图保存、精度可调节。

> 公式适用域按**真正参与计算的温度**判定，不按用户填的迭代初值；超出范围的公式会明确显示「不适用」，不会与有效结果并列展示。

## 实测能力与精度

> 下面每一张表都由 `python -m pytest -q` 复算。表格里的数字就是断言里的数字——
> 改坏了会变红，不会悄悄过期。

### 饱和水汽压公式实测偏差（对照 WMO/Smithsonian 参考表）

| 公式 | 注册适用域 | 最大偏差 | 出现位置 |
|---|---|---:|---|
| Goff-水面 | −10 ~ 100 ℃ | 0.09% | 15 ℃ |
| Goff2-水面（Goff-Gratch 1946） | −10 ~ 100 ℃ | 0.09% | 0 ℃ |
| Wexler-水面 | −10 ~ 200 ℃ | 0.09% | 100 ℃ |
| Tetens-水面 | 0 ~ 50 ℃ | 0.09% | 40 ℃ |
| August-水面 | 0 ~ 60 ℃ | 0.23% | 20 ℃ |
| Buck-水面 | 0 ~ 80 ℃ | 0.24% | 50 ℃ |
| Magnus-水面 | 0 ~ 60 ℃ | 0.27% | 20 ℃ |
| Gili-水面 | −10 ~ 20 ℃ | 0.28% | 15 ℃ |
| Arden-水面 | 0 ~ 100 ℃（**仅 0~25 ℃ 内可用**） | 1.0% @25 ℃、3.6% @50 ℃、12.7% @100 ℃ | 100 ℃ |
| Goff-冰面 | −100 ~ 10 ℃ | 0.09% | −50 ℃ |
| Wexler-冰面 | −150 ~ 10 ℃ | 0.04% | −40 ℃ |
| Magnus-冰面 | −65 ~ 0 ℃ | 0.02% | −50 ℃ |
| Buck-冰面 | −80 ~ 0 ℃ | 0.03% | −20 ℃ |
| Marti-冰面 | −150 ~ 0 ℃ | 1.29% | −50 ℃ |

> 为什么 Goff/Goff-Gratch/Wexler 的偏差能作为"表本身对不对"的证据：它们与 WMO 参考表
> 互差 ≤0.09%，两者互相印证，而不是自说自话。
> **Arden-水面 需要特别注意**：它注册的适用域是 0~100 ℃，但高温端不可用（原因见「已知限制」）。

### 极端温度下真正给出结果的公式数

| 干球温度 | 相对湿度 | 给出结果的公式数 |
|---|---:|---:|
| −150 ℃ | 60% | **0 / 14** |
| −100 ℃ | 60% | 3 / 14 |
| −80 ℃ | 60% | 4 / 14 |
| 0 ℃ | 60% | **14 / 14** |
| 45 ℃ | 60% | 8 / 14 |
| +150 ℃ | 50% | **0 / 14** |
| +200 ℃ | 50% | **0 / 14** |

> 不要被"注册适用域覆盖 −150~200 ℃"误导：**高温端的 150/200 ℃ 一个公式都不给结果**。
> 本工具真正可用的范围是约 −80 ~ 50 ℃；超出时界面会显示「不适用」，而不是硬凑一个数。

### 湿球温度的独立交叉验证

| 参照 | 参照性质 | 实测最大偏差 |
|---|---|---|
| ASHRAE 绝热饱和定义式 | 湿球温度的**严格定义**（不含 Lewis 关系近似） | **0.45 K**（50 ℃ / RH 10% 处；常温约 0.05 K） |
| Stull (2011) 经验式 | 与本站零共享代码的独立拟合 | 0.91 K |
| ASHRAE/Vaisala 露点换算表 | 公开表值 | 0.30 K（断言容差内） |

> 本站解的是气象学湿度计方程 `e = e_sat(T_w) − A·p·(T − T_w)`，`A = 0.000667(1+0.00115·T_w)`。
> 与 ASHRAE 严格定义式的差是**该近似本身的误差**：随温度升高、空气变干而单调增大（0.01→0.45 K），
> 形态平滑可解释。若将来这个差变成随机跳变或反号，说明求解器坏了，CI 会立刻报红。

### 1.3.1 更新内容！（数值修复版）

> **v1.3.1 的数值结果与 v1.3.0 不同**，因为修掉了三处公式缺陷。请以 v1.3.1 为准。

- **修复**：`Gili-水面` 的前因子误写为 980.66（= 1 工程大气压），导致该式全区间恒定偏低 **约 3.0%**；
  改为参考点（373.16 K 水沸点）对应的 1013.25 hPa 后偏差降到 **0.28% 以内**。
- **修复**：`Goff2-水面`（Goff-Gratch 1946）的第 4 个系数误写为 `1.3816e-5`，标准值为 `1.3816e-7`；
  低温端因此偏 −3.5%（0 ℃）～−1.7%（10 ℃），修正后全区间 ≤0.09%。
- **修复**：`goff` 族的解析导数第二项写错（`C/A·log10(Tk/A)·ln10` 应为 `C/(Tk·ln10)`），
  使 Goff-水面 26%、Goff2-水面 40%、Goff-冰面 18% 的斜率是错的（根不变，所以只看结果发现不了）。
- **修复**：扩展参数面板的三处物理量——湿空气声速（比热容误用**摩尔**气体常数，295 → 347 m/s）、
  水蒸气密度与含湿量（误用湿球饱和水汽压）、饱和混合率（误用实际水汽压，11.89 → 20.08 g/kg）。
- **修复**：相当位温的潜热项量纲（`L_v` 以 kJ/kg 给出却直接除以 J/(kg·K) 的 `Cp`，
  相当于潜热被缩小 1000 倍，θe 退化成 θ）。
- **新增**：引擎层（`core.py`）输入校验——温度、压强、相对湿度在计算核心里强制校验，
  批量计算路径同样受保护；不再出现 RH=0 时返回 −150 ℃ 这种"贴着边界的假数值"。
- **修复**：公式适用域按真正参与计算的温度判定（此前按用户填的迭代初值判定，
  会出现冰面公式在 15 ℃ 露点下照常出数）。
- **新增**：`tests/` 外部参照回归（236 条断言）+ GitHub Actions CI + `run_tests.ps1`。
- **移除**：`pyuic5` 生成文件表头里的个人绝对路径。

## 开发与验证

### 一条命令跑全部检查（本地）

```powershell
pwsh -File run_tests.ps1
```

等价于依次执行：语法编译 → 静态检查 → 计算核心等价性回归 → 对照公开参考值的正确性验证。

### 分开跑

```bash
python core.py            # 等价性回归：确认重构没有改变 Goff-水面 的数值（零依赖）
python -m pytest -q       # 正确性验证：对照 WMO/ASHRAE 公开参考值（238 条断言）
python -m pyflakes core.py main.py   # 静态检查：未定义名 / 未使用导入
```

> 两者的分工很重要：`python core.py` 是**自我回归**（对照自己上一版的输出），
> 构造上发现不了继承来的系统偏差；**正确性必须由 `tests/` 里的外部参考值兜底**。

### CI

`.github/workflows/tests.yml` 在每次 push / PR 时于 Linux 干净机器上重跑：
Python 3.10 与 3.12 双版本 · 核心回归 · 参考值验证 · 全部源文件语法编译 · 静态检查。
判定成败的唯一依据是**退出码**——不看任何打印信息（`print("验证通过")` 不是测试）。

### 目录结构


## 批量计算使用方法
- **1**：在主页面选择计算模式，选择单位。
- **2**：将数据中的干球温度拷入 example.xlsx 中的 A 列，根据模式将露点/湿球/相对湿度拷入 B 列，大气压强拷入 C 列。
- **3**：点击批量计算，静待即可！☕
### 注意事项❗
- **确保 xlsx 在 exe 的同一目录下并且只有一个 xlsx 文件**：否则可能不会计算或报错。
- **确保第一行有 ABCDEF 列**：否则报错
- **结果会被保存在新的文档中！**
- 批量计算使用 `Goff-水面`（干球 ≥ 0 ℃）或 `Goff-冰面`（干球 < 0 ℃），单行输入非法时该行结果留空，不会中断整个文件。

## 已知限制

> 这一节和上面的精度表同等重要：**一个工具的边界写不清楚，它的结果就不能被信任。**
> 下面每一条都有对应的断言或注释，不是"据说"。

1. **高温端不可用**：+150 ℃ / +200 ℃ 时 14 条公式一条都不给结果。注册适用域覆盖到 200 ℃，
   但那是公式的声明而不是实际能力（见上表）。
2. **Arden-水面 高温端不可用**：`Arden-水面` 的系数取自 Buck (1996) 的**三参数**式
   `e_s = 6.1121·exp[(18.678 − T/234.5)·T/(257.14 + T)]`，注册时被套进 `magnus` 族的**两参数**式，
   丢掉了 `−T/234.5` 修正项 → 25 ℃ 偏 +1.0%、50 ℃ 偏 +3.6%、100 ℃ 偏 +12.7%。
   目前只在 README 中标注；若需要它在高温端可用，应新增一个三参数族。
3. **湿球方程用的是湿度计近似**：与 ASHRAE 绝热饱和定义式相差 0.01~0.45 K（随温度升高而增大）。
   要做严格意义上的热力学湿球温度，需要改用绝热饱和方程。
4. **湿球在 0 ℃ 以下仍按水面饱和**：真实通风干湿表在结冰时是"冰球"，应按冰面饱和计算；
   本工具统一按所填的公式族计算，跨 0 ℃ 时不同公式的结果会因此分叉。
5. **抬升凝结高度用的是 Bolton 式的一个常见变体**，其中 `T_d − 56` 按摄氏度代入
   （标准 Bolton 式按开尔文）。实测与"LCL 高度 ≈ 125(T−T_d) 米"经验规则相差 ≤1.2 K，
   但与严格 Bolton 解有约 1 K 的偏差，尚未用外部真值核对。
6. **重力加速度设置不参与任何计算**：它只写入 `cfg.json` 并更新界面占位符。
   `v1.2.0` 的更新说明中"可以自定义本地重力加速度（使得计算结果更加准确）"这句话不成立。
7. **批量计算不落盘中间结果**：整表处理完才写 `result_*.xlsx`，中途出错需重跑。
8. **GUI 未纳入自动化测试**：`main.py` 依赖 PySide2，CI 只做语法编译。
   界面交互（单位对话框、批量落盘）目前仍需人工验证。
